# GM 통합관리도구

지엠로드 · 지엠알 · OO엔지니어링 3개 회사를 한 곳에서 관리하는 프로그램입니다.
PC · 태블릿 · 폰(Android / iOS)에서 같은 주소로 열리고, 폰에서는 홈 화면에 앱처럼 설치할 수 있습니다(PWA).

- 화면 설계: 디자인 캔버스 **"지엠 통합관리도구 v2 - 재설계 디자인"**
- 메뉴 구성: 프로젝트 문서 `지엠로드_통합관리도구_메뉴·페이지_재설계.md`

## ⚠️ 주의 — 지금은 테스트 운영입니다 (개인 홈 서버)

정식 도입 전까지는 **개발자 개인 홈 서버**(Ubuntu 미니 PC · CPU 4코어 · 메모리 14GB)에서 시험으로 돌립니다. 회사 서버를 구축하면 전부 옮깁니다.

- **실제 업무 자료는 최소한만** 올려 주세요. 시험용 자료 위주로 쓰고, 중요한 원본(계약서 · 내역서 원본 등)은 기존 보관처에도 꼭 남겨 두세요.
- **서버가 꺼지면 접속이 안 됩니다.** 가정용 전기 · 인터넷이라 정전 · 공유기 재부팅 · 업데이트 중에는 잠시 열리지 않을 수 있습니다. 급한 업무를 이 프로그램에만 의존하지 마세요.
- **백업은 수동입니다.** 큰 작업 전후로 `bash scripts/backup.sh`를 실행합니다. 디스크가 고장 나면 마지막 백업 이후 자료는 되살릴 수 없습니다.
- **회의 받아쓰기가 느립니다.** 1시간 회의는 받아쓰는 데 30분~1시간쯤 걸립니다(한 번에 하나씩 차례대로). 그동안 서버 CPU를 거의 다 써서, 같은 서버의 다른 서비스와 이 프로그램 화면이 잠깐 느려질 수 있습니다.
- **녹음 파일 크기:** 수파베이스 기본 설정으로는 50MB가 넘는 파일을 올릴 수 없습니다(이 프로그램에서 녹음하면 1시간 약 15MB).
- **외부 접속은 Tailscale로만** 합니다(https://workniumserver.tail876d9c.ts.net). Tailscale에 초대된 기기에서만 열립니다. 녹음 · 카메라는 https 주소에서만 됩니다.
- **AI 요약 · 손글씨 인식**은 서버 `.env`의 Claude API 키로 동작합니다. 키를 넣은 사람의 계정으로 사용료가 나갑니다. 녹음 자체는 서버 밖으로 나가지 않고, 요약할 때만 받아쓴 글자와 사진이 Claude API로 전송됩니다.
- **계정 · 비밀번호:** 시험이 끝나 회사 서버로 옮길 때 임시 비밀번호와 내역서 · 회의록 잠금 해제 비밀번호를 새로 정합니다.

### 지켜지는 규칙
- 금액은 모두 정수, 곱셈은 `TRUNC(A × B)` (DB 뷰와 화면 모두)
- 공정률(금액 기준) = Σ TRUNC(승인된 누계수량 × 도급단가) ÷ Σ TRUNC(설계수량 × 도급단가)
- 현장에서 넣은 수량은 **본사 승인 후** 공정률에 반영 (DB가 강제)
- 사진: 현장 담당자는 자기가 올린 사진만 고치거나 지우고, 본사는 전부 (DB가 강제). 사진 날짜는 한국 시간 촬영일 기준
- 저장소 파일 경로는 영문 · 숫자로만 만듭니다 (수파베이스 저장소가 한글 경로를 거부). 화면에 보이는 파일 이름은 DB에 따로 저장되어 그대로 한글로 보입니다
- 권한은 DB(RLS)가 지킵니다 — 타사 프로젝트는 화면에서 숨기는 게 아니라 아예 조회가 안 됩니다

## 구조

```
gmroad/
├─ supabase/migrations/001_init.sql   DB 스키마 · 권한(RLS) · 공정률 뷰 · 파일 저장소 규칙
├─ web/                               React 웹앱 (PC · 태블릿 · 폰 · PWA) → nginx 컨테이너
├─ api/                               관리 API (계정 생성 · 비밀번호 초기화) + 기본 관리자 만들기
├─ scripts/                           setup · migrate · update · backup · restore
└─ docker-compose.yml                 web + api 두 컨테이너
```

- **수파베이스는 홈 서버에 이미 떠 있는 셀프호스팅(~/supabase/docker)을 그대로 씁니다.** 호비스가 쓰는 `public` 스키마와 섞이지 않게 모든 테이블은 `gm` 스키마에 있습니다.
- 브라우저는 수파베이스에 직접 붙지 않고 **같은 주소의 `/sb`** 로 접속합니다(nginx가 중계). 그래서 HTTPS 주소 하나로 웹앱 · DB · 파일 · 실시간 알림이 모두 동작합니다.

```
폰 / PC ──HTTPS──▶ tailscale serve ──▶ web(nginx :8080) ─┬─ /      웹앱
                                                         ├─ /api   → api 컨테이너 (service key)
                                                         └─ /sb    → 수파베이스 Kong :8000
```

## 홈 서버에 설치 (처음 한 번)

홈 서버(우분투 미니 PC)에 SSH로 접속해서:

```bash
cd ~
git clone https://github.com/worknium-lab/gmroad.git
cd gmroad
bash scripts/setup.sh
```

`setup.sh`가 하는 일:
1. `~/supabase/docker/.env`에서 ANON_KEY · SERVICE_ROLE_KEY를 읽어 `.env` 생성
2. 수파베이스 API 설정 `PGRST_DB_SCHEMAS`에 `gm` 추가 (원본은 `.env.bak.날짜`로 백업) 후 rest 재시작
3. DB 마이그레이션 적용
4. 웹앱 · API 빌드하고 실행 (`http://서버IP:8080`)
5. 기본 관리자 `gmconst` 생성 — **임시 비밀번호 `gmconst`**, 첫 로그인 때 새 비밀번호를 정합니다

### 밖에서 HTTPS로 쓰기 (폰 필수)
폰 카메라 · GPS · 홈 화면 설치는 HTTPS에서만 됩니다. 테일스케일이 이미 깔려 있으니:

```bash
sudo tailscale serve --bg 8080
tailscale serve status        # https://워크니움서버.xxxx.ts.net 주소 확인
```

테일스케일 앱이 깔린 폰 · 노트북에서 그 주소로 접속합니다. (처음 한 번 테일스케일 관리 화면에서 HTTPS 인증서 사용을 켜야 할 수 있습니다.)
폰에서 접속 → 브라우저 메뉴 **"홈 화면에 추가"** 하면 앱처럼 열립니다.

## 평소 쓰는 명령

| 하려는 것 | 명령 |
|---|---|
| 새 버전 받기 | `bash scripts/update.sh` (코드 받기 → DB 마이그레이션 → 다시 빌드) |
| 상태 보기 | `docker compose ps` · `docker compose logs -f web api` |
| 백업 | `bash scripts/backup.sh` → `backups/날짜/` (DB · 계정 · 업로드 파일, 최근 14개 보관) |

| 멈추기 / 다시 띄우기 | `docker compose down` / `docker compose up -d` |

## 회사 서버로 옮길 때

1. 회사 서버(Ubuntu)에 도커 · 수파베이스 셀프호스팅을 설치합니다 (홈 서버와 같은 방법).
2. 홈 서버에서 `bash scripts/backup.sh` → 생긴 `backups/날짜/` 폴더를 회사 서버로 복사.
3. 회사 서버에서 `git clone` → `bash scripts/setup.sh` (새 DB에 스키마 생성).
4. `bash scripts/restore.sh backups/날짜` → 데이터 · 계정 · 파일 복원.
5. 접속 주소만 바뀝니다. 코드 · 설정 구조는 그대로입니다.

> 계정(auth.users)도 함께 옮겨지므로, 모두 같은 비밀번호로 그대로 로그인할 수 있습니다.

```bash
cd web && npm install
SB_TARGET=http://192.168.219.104:8000 npm run dev     # 홈 서버 수파베이스에 연결
```
`web/public/config.js`의 `SUPABASE_ANON_KEY`에 키를 넣어야 로그인됩니다 (커밋하지 마세요).

DB를 바꿀 때는 `supabase/migrations/002_xxx.sql`처럼 새 파일을 추가하고 `bash scripts/migrate.sh`로 적용합니다. 이미 적용한 파일은 고치지 않습니다.

## 앱 알림(푸시) 켜기

따로 설정할 것은 없습니다. API가 처음 켜질 때 푸시 키를 만들어 DB(`gm.push_keys`)에 보관합니다 — **이 키를 지우거나 바꾸면 모든 기기에서 알림을 다시 켜야 합니다** (회사 서버로 옮길 때 DB를 통째로 옮기면 그대로 이어짐).

- 반드시 **https 주소**로 접속해야 합니다 (지금은 Tailscale 주소 `https://workniumserver.tail876d9c.ts.net`).
- 안드로이드 · PC: 크롬 · 삼성 인터넷 · 엣지에서 *내 정보 › 앱 알림 › 이 기기에서 알림 받기*.
- 아이폰 · 아이패드: 사파리에서 *공유 → 홈 화면에 추가*로 앱을 깐 뒤, **그 앱 안에서** 알림을 켜야 합니다 (iOS 16.4 이상).
- 로그아웃하면 그 기기로 가던 알림이 끊기고, 다른 사람이 같은 폰으로 로그인하면 그 사람 알림으로 바뀝니다.

## 라이선스 (납품용 접근 제어)

사용 기한은 **WORKNIUM 라이선스 서버가 전자서명(Ed25519)하고 암호화한 라이선스**로만 바뀝니다. 서명 개인키는 라이선스 서버의 `/data/keys`에만 있어서, 그 밖의 누구도(고객사 관리자 · DB 직접 수정 포함) 기한을 늘릴 수 없습니다.

| 단계 | 언제 | 쓸 수 있는 것 |
|---|---|---|
| 정상 | 사용 기한(선불한 달의 말일)까지 | 전부 |
| 미입금 알림 | 마지막 달 10일이 지나도 다음 달 입금 없음 | 전부 · 관리자에게 주황 띠 |
| 유예 | 기한 후 1~7일 | 전부 · 모두에게 빨간 띠 |
| 읽기 전용 | 8~38일 (+ 백업 연장, 1일 10만 원) | 보기 · 엑셀 내려받기 · 백업만 |
| 차단 | 그 뒤 | 안내 화면만 (데이터는 지우지 않음) |

어느 단계든 [입금 확인] → 다음 확인(하루 1번, 또는 고객 화면 [지금 확인]) 때 바로 정상.

**지켜 주는 장치**
1. 라이선스 파일: 서명 + 암호화. 한 글자라도 바꾸면 무효, 다른 서버용 파일은 안 들어감
2. DB 잠금: 단계를 DB가 날짜로 직접 계산. 읽기 전용 · 차단이면 모든 테이블 · 파일 쓰기를 DB가 막음 (새 테이블도 자동). 서버 시계를 되돌려도 소용없음. 라이선스 행을 지우면 차단
3. 위변조 감지: 매일 프로그램 파일 지문을 라이선스 서버에 보고 → 한 글자라도 바뀌면 즉시 읽기 전용 + 대표님 폰 알림. DB의 라이선스 값을 직접 고쳐도 감지. 같은 키를 다른 서버에서 쓰면 승인 전까지 읽기 전용
4. 배포판: 고객 서버에는 소스 없이 난독화된 완성 프로그램만 (`scripts/release.sh`). 실제 고객이 GitHub 소스(개발판)로 돌리면 '등록되지 않은 프로그램'으로 읽기 전용

※ 서버 관리자 권한 · 디스크 암호화(서버 잠금)는 넣지 않기로 했습니다. 고객 서버의 관리자 권한을 가진 사람이 작정하고 해킹하는 것은 어떤 프로그램도 100% 막을 수 없으므로, 그 경우에도 **바로 알 수 있게**(3번) 하고 계약서의 변조 · 재배포 금지 조항으로 대응합니다.

### 처음 설정 (대표님 홈 서버 — 지엠로드 테스트)
1. `.env` 에 추가: `COMPOSE_PROFILES=stt,license` · `LICENSE_URL=http://host.docker.internal:8090` → `bash scripts/update.sh`
2. 같은 네트워크(Tailscale)에서 `http://workniumserver:8090` 열기 → 처음 넣는 비밀번호(8자 이상)가 관리 비밀번호
3. [고객사 등록] → 지엠로드, **개발판 허용 켬**(홈 서버는 GitHub 소스로 돌기 때문), 처음 사용 기한 = 계약 시작일 (계약 전 무료)
4. 나온 고객 키를 `.env` 의 `LICENSE_KEY=` 에 넣고 `docker compose up -d` → 통합관리 › 관리자 › 라이선스에서 [지금 확인]
5. 대표님 폰 알림(위변조 · 새 설치)은 https 주소에서만 켜집니다: `sudo tailscale serve --bg --https=8443 http://localhost:8090` → `https://workniumserver.tail876d9c.ts.net:8443` 에서 [이 폰으로 알림 받기]
6. **서명 키 백업 (반드시)**: `docker run --rm -v gm-integrated_license-data:/d -v $PWD:/b alpine tar czf /b/license-backup.tgz -C /d .` → 안전한 곳에 보관. 잃어버리면 모든 고객사 라이선스를 다시 발급해야 하고, 남에게 넘어가면 누구나 라이선스를 만들 수 있습니다

설치 직후에는 라이선스 서버에 연결하지 않아도 **60일 동안 정상**으로 씁니다(설정 기간). 그 안에 위 설정을 마치세요.

### 고객사에 납품할 때
1. `LICENSE_URL=… LICENSE_ADMIN_PASSWORD=… bash scripts/release.sh 2026.12.01 ghcr.io/worknium-lab` → 난독화 이미지 + 지문 등록 + 설치 꾸러미(`gm-install-버전.tgz`)
2. 고객 서버: 수파베이스 설치 → 꾸러미 풀기 → `.env` 작성(고객 키) → `bash scripts/migrate.sh` → `docker compose up -d`
3. 라이선스 관리 화면에서 그 고객사는 **개발판 허용을 끈 채로** 둡니다

## 회의록 받아쓰기 · 요약 켜기

1. `.env` 에 아래를 넣습니다 (`nano .env`).
   ```
   COMPOSE_PROFILES=stt
   WHISPER_MODEL=large-v3-turbo
   ANTHROPIC_API_KEY=sk-ant-...      # 요약 · 손글씨 인식 (없으면 받아쓰기까지만)
   ```
2. `bash scripts/update.sh` — 받아쓰기 서버(stt)가 처음 한 번 만들어지고, 첫 녹음 때 모델(약 1.6GB)을 내려받습니다.
3. 서버가 느리면 `WHISPER_MODEL=medium` 이나 `small` 로 바꿉니다 (빠르지만 덜 정확).
4. 녹음은 이 서버 안에서만 받아쓰고 밖으로 보내지 않습니다. 요약 · 손글씨 인식만 Claude API로 글자/사진을 보냅니다.
5. 휴대폰 녹음파일이 50MB를 넘으면 수파베이스 `~/supabase/docker/.env` 의 `FILE_SIZE_LIMIT` 를 늘려야 올라갑니다.
